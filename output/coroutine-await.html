协程与 await：一个能暂停的函数

协程 = 能暂停、能恢复的函数。await = 暂停，并把"我在等什么"交给驱动者。坐标来自 CPython 3.11 标准库。

4本质只有三行

# asyncio.Future.__await__  —— 整个 await 机制的缩影
def __await__(self):
    if not self.done():
        yield self          # 我不行，把"等什么"交给 Task
    return self.result()    # 好了，取结果（也可能抛）

await x 约等于 yield from x.__await__()。当前协程的 frame 停住，yield 出来的东西往上冒泡给 Task。

5await 的四种结局

await fut · 已完成

if 不成立 → 不 yield、不让出、原地取值。白等但没代价。

await fut · 未完成

yield self → Task 挂 callback，返回事件循环。真挂起。

await fut · 失败

result() 抛异常 → 被 throw 回 await 所在那一行。

await coro · 直接等协程

你亲自驱动它，它是你调用栈上的一层。别的 Task 并发不了。

6coroutine / Task / Future / thread

coroutine惰性。不能自己跑，没有调度，没有身份。调用只是产出一个对象。
TaskFuture 的子类。驱动 coroutine，把自己注册进事件循环，并持有结果。
事件循环select/epoll + ready 队列。只有 1 条 OS 线程，一次只跑一个 Task。
Future"未来会有的值"的凭证。await 它 = 等别人 set_result。
threadOS 调度，抢占式，有自己的栈。和上面这一套毫无关系。

7对照 Java 21 虚拟线程

两者都是用户态并发。差别在谁定义让出点，以及调度器跑在几条 OS 线程上。

async def fetch(url):
    text = await http_get(url)      # ← 唯一让出点，我写的
    return parse(text)

async def handle():
    a = await fetch(u1)           # ← 传染：调用者也得是 async

// Java：让出点在 JDK 里，你的代码和阻塞版一模一样
String fetch(String url) {
    String text = httpGet(url);   // ← 阻塞调用，JVM 自动 unmount
    return parse(text);
}
void handle() throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        var a = scope.fork(() -> fetch(u1));   // ← 无传染，普通方法
    }
}

抢占式?否，纯协作否，也是协作（只在阻塞点 unmount）

两个反直觉的点。① 虚拟线程不是抢占式 —— 它只在阻塞点 unmount，CPU 密集循环不会 yield，Javadoc 明确说不适合长时间计算。 ② 正因如此，跨语言的对应关系是反的：Java 里最像 Python 协程的是 Reactor / CompletableFuture 那套链式 API（显式让出 + 传染）；Python 里最像虚拟线程的是 gevent / eventlet 的猴子补丁（把 socket、sleep 换掉，代码不用改）。虚拟线程的本质就是"把 gevent 那套做进 JVM，并且能跑在多条 carrier 线程上"。

JDK 21 的坑：synchronized 块和 Object.wait() 会 pin 住 carrier 线程（无法 unmount），到 JDK 24 的 JEP 491 才修。Python 侧没有 pinning 这个概念，对应的坑是"在协程里调阻塞函数"。

9最常错的三点

调用 async def 会执行

不会。只产出一个 coroutine 对象，一个字都不跑。

await 一定会切换

不会。目标已完成，或目标内部没有真挂起点时，原地继续。

协程的 return 是函数返回

不是。它打包成 StopIteration.value 送给驱动者。
