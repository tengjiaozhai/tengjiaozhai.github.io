Pi Durable：断了怎么接着跑

每一步都是 task，先存 checkpoint 再往下走。工具调用前先记下「我要调它」。恢复时看存储就知道谁没跑完；重不重跑，看工具定义时写没写 replay: "safe"。

1三个工具，C 跑到一半进程挂了

存储里的记录（示意）。工具调用的 intent 在执行前落盘：原文 "its intent is stored before it runs"。

工具 A
记录：开始记录：完成 + 结果
工具 B
记录：开始记录：完成 + 结果
工具 C
记录：开始⚡ 没有「完成」
💥 进程死亡（笔记本睡眠 / 容器重新部署 / OOM）→ 新进程打开同一个存储，harness.resume()
恢复时不需要判断「C 当时在不在跑」：有开始、没完成 = 被打断。A、B 的结果已存好，不重跑。接下来只看 C 的工具定义：
replay: "safe"

只重跑 C。官方度假规划 demo：天气、博物馆已完成，火车票没完成；search 是 safe，所以只有火车票重跑。

没写 replay

不重跑。告诉模型「这次调用被中断了」，并附上已存下的输出，由模型决定下一步（先查现状、补写、重来或问人）。

同时：被切断的模型请求会重新发送，已生成的半截回答留在 transcript 里，标记为 aborted；排队中的消息仍在排队；带 requestId 的提交是 exactly-once，客户端崩溃后重试拿回的是原来那次提交。
2safe 是什么时候标的？

常见误解：中断那一刻给「正在跑的工具」打上 safe。实际上是写工具的人在定义时声明的，是工具本身的性质。

const searchIssues = defineTool({
  name: "search_issues",
  replay: "safe", // only reads, so a rerun after a crash is fine
  execute: ...
});
const deploy = defineTool({
  name: "deploy",
  // No replay: a deploy interrupted by a crash is reported to the model, never repeated.
  execute: ...
});
3我的工具能标 safe 吗？
重跑一次会不会产生额外副作用？
↓
只读 → 可以标 safe
↓ 有写操作
能做成幂等吗？（重做多少次 = 做一次）
↓
幂等键 payment-${task.id} / requestId · 覆盖而不是追加 · 先查再写（triage 先找已有子 agent）→ 可以标 safe
↓ 做不到
不标 → 中断交给模型判断；高风险操作再加审批 hook，决定存进 memo（first write wins），重启后不再重复问人
