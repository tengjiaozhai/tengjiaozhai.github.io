AGENTSCOPE · PYTHON ASYNC CONTROL FLOW

一个 yield，一个 raise，还有一个队列哨兵

boom_tool 的问题不是“异常凭空消失”，而是旧代码在异常传播前先交出了一条假的成功终态。 把事件流、异常流和队列拆开，就能看懂为什么 responses == [] 反而是正确测试结果。

yield = 交出事件并暂停 await put = 放入中间邮箱 sentinel = 生产结束标记 raise = 沿调用链抛异常

03 · 三个关键字，各管一条通道

yield

异步生成器把一条 ToolChunk 或终态 ToolResponse 交给调用方，然后保留 frame，等待下一次拉取。

Java 近似：sink.next(chunk) / 迭代器产生一个元素。

raise

DeveloperOrientedException 沿调用链向上抛；它不是工具结果，也不会自动进入队列。

Java 近似：throw new DeveloperOrientedException(...)。

await put

queue.put 把消息放到中间队列。默认无界队列通常立即完成；有界队列满时才会挂起。

Java 近似：blockingQueue.put(item)，不等于发给浏览器。

04 · _QUEUE_SENTINEL 是“生产结束”，不是异常

后台任务把异常对象和哨兵都当作消息放入队列；消费者必须先识别消息类型。

05 · 旧代码与修复形状

# 旧代码：finally 无条件产出终态
try:
    ...
except Exception as e:
    if isinstance(e, DeveloperOrientedException):
        raise e from None
finally:
    yield tool_response
    # boom 时也会是默认 SUCCESS + []
# 修复形状：只在成功或已处理错误后产出
try:
    ...
except DeveloperOrientedException:
    raise

yield tool_response
# 未处理异常不再先拿到假的终态

06 · 为什么 responses == [] 是 PASS

responses = []
with self.assertRaisesRegex(DeveloperOrientedException, "boom: repro"):
    async for item in agent._acting(tool_call):
        responses.append(item)

self.assertEqual(responses, [])
修复后：第一个结果尚未交付，异常先到达 assertRaisesRegex；空列表证明没有假的 SUCCESS。
旧代码：空 ToolResponse 先进入列表，消费者提前停止；预期异常没有到达，测试失败。
代码坐标：AgentScope examples/agent_service/main.py、src/agentscope/tool/_toolkit.py、src/agentscope/app/middleware/_tool_offload_middleware.py。
语义边界：修复“空 SUCCESS 遮住致命异常”不等于自动修复 asking / awaiting_permission 的会话收尾；两者是相邻但独立的生命周期问题。
