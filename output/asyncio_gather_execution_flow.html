9 步流程 详细执行时序拆解
调用协程函数，生成协程对象
调用 search_flights() 和 search_hotels()，由于是 async def，并不会立即执行，而是返回两个 coroutine object。
asyncio.gather 包装 Task 并排队
gather 接收这两个协程，将它们打包成 asyncio.Task，并注册进事件循环的就绪队列，返回一个聚合 Future。
主流程遇到 await，让出线程控制权
await asyncio.gather(...) 触发让出点，当前函数暂停，控制权交回给 Event Loop（事件循环）。
事件循环调度 Task 1 (search_flights)
事件循环运行 Task 1，提取上下文 contextvars，直到执行到 await asyncio.sleep(0.15)。
Task 1 让出，事件循环立即无缝切换到 Task 2
Task 1 注册定时器后让出控制权。单线程不休眠，事件循环立刻拉起队列中的 Task 2 (search_hotels) 开始执行。
Task 2 也遇到 await，双方 I/O 并发等待
Task 2 执行到 await asyncio.sleep(0.15) 也让出控制权。此时两个任务的外部 I/O 同时在后台等待。
I/O 完成，事件循环依次唤醒 Task 1 和 Task 2
定时器到期后，事件循环依次唤醒两个任务，分别执行后续的数据拼装并返回数据字典。
gather 严格保序组装结果
即使 Task 2 比 Task 1 先完成，gather 也会严格按照参数顺序组装成元组 (flights, hotels)。
主流程唤醒，解包赋值
主流程从 await 处被唤醒，flights, hotels = ... 成功解构，继续向下执行。
核心特性 Java 工程师易踩坑点
特性维度 asyncio.gather (Python) CompletableFuture.allOf (Java)
线程开销 全程 1 条系统线程，协程切换是用户态跳转，开销极小 依赖 ForkJoinPool 或线程池，多线程物理并行
返回值提取 原生返回有序元组 flights, hotels = await gather(...) allOf() 返回 Void，需手动 f1.join(), f2.join() 提取
上下文传递 每个 Task 自动做 contextvars 浅拷贝（协程安全） ThreadLocal 无法跨线程池自动传递，需 TransmittableThreadLocal
