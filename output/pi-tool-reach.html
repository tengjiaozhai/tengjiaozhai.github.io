Pi 的三条工具到达路径

模型要碰到一个工具，官方文档写了三条能干活的路：direct、deferred + tool_search、codemode。图里每条路都标出「模型看见什么」和「结果怎么回来」。

0先把名字说清楚

口述的两个名字没有官方对应项

「to explorer」和「to tour out」在 pi.dev/docs/latest 与仓库 earendil-works/pi 里没有同名模式。本图用文档里的正式名字。包索引上的 pi-explorer、pi-compass 的 /tour 是第三方扩展，不在这三条路径里。

1同一句话，三条回路

起点都是模型这一轮要完成任务。分叉点是：工具声明在不在这次请求里，以及工具结果要不要先经过一段脚本。

direct
声明已在请求里像 read / bash 一样
→
模型直接发工具调用参数是该工具的 JSON
→
真执行权限钩子照走
→
结果进上下文MCP 文本超过 20 KB 会截中间
deferred
声明不在请求里exposure = deferred
→
模型调用 tool_searchBM25，默认 8 条
→
命中工具被激活写入会话，留在这条分支
→
下一次模型调用起直接调之后走 direct 那条结果回路
codemode
模型调用 codemode参数是纯 JS，不是 JSON
→
QuickJS 沙箱当作 async 函数体
→
tools.名字(args)可并行；调用是真执行
→
只有脚本输出回模型大结果先在脚本里滤掉

三条路差在「谁看见中间结果」

direct 和被 tool_search 加载之后的调用，都是一次工具调用对应一条回到模型的结果。codemode 把许多次真工具调用关在沙箱里，模型只看见脚本用 text()、image()、return 和 console 交出去的那一份。

2每条路怎么走

direct

声明在，就直接调

  1. 工具以普通工具声明出现在模型请求里。
  2. MCP 上这是小而常用的那一组。带 direct 工具的服务器，第一条 prompt 最多等 10 秒，好把声明放进这次请求。
  3. 脚本里也能调它：tools.名字(args)。
  4. 适合：工具少、几乎每次都要用、希望模型不用搜索就看见参数。
deferred + tool_search

先搜索，再变成直接调用

  1. 工具已注册，但还没声明给模型。
  2. 有 deferred 的 MCP 服务器连上时，Pi 会激活 tool_search。也可以自己写 "defaultTools": ["+tool_search"]。
  3. tool_search 用和脚本里 searchTools() 相同的 BM25。参数是 query，可选 limit（默认 8，必须是正整数）。它自己的 exposure 是 model-only：模型能调它，脚本不能通过 tools.tool_search 再调它。
  4. 命中项用 setActiveTools 激活，从下一次模型调用起声明出来，并记进会话。这条分支上 /tree、resume、fork 都还在。
  5. 它只搜索 exposure 为 codemode 或 deferred、且当前还没激活的工具。
  6. 适合：工具很多，找到之后希望模型像调内置工具一样直接调，而不是包进脚本。
codemode

写一段 JS，只把结论交回去

  1. 输入是原始 JavaScript，不是 JSON，也不是 Markdown 代码块。在 QuickJS 里作为 async 函数体运行，顶层可以用 await 和 return。
  2. 沙箱没有 Node API、文件系统、网络、定时器。出去只靠 tools.* 和 models。
  3. 工具名里不能做 JS 标识符的字符会变成 _。并行用 Promise.all / Promise.allSettled。失败、被拦截、参数不合法会 reject；已经发生的调用不回滚。
  4. 发现工具用 searchTools（BM25，默认 8 条）、describeTool、describeNamespace、ALL_TOOLS。这几步不会把工具声明塞进下一次模型请求；那是 tool_search 的事。
  5. store / load 在成功的脚本之间保存小 JSON。单值最多 262144 字符，合计最多 1048576。失败的脚本不保留这次写入。
  6. 适合：要并行、要过滤大结果、要在一次模型往返里串多步，或者要跑分类器 / 出图。

3Codemode 沙箱内部

输出怎么回到模型

结果以 Script completed 或 Script failed 开头，带上耗时。正文来自 text()、return、image()，console.* 集中在后面的 <console_output>。失败时保留已经产生的输出，再附上 Script error:。脚本结束时还在跑的调用会被取消，没 await 的 promise 丢掉。

选项行和开关

脚本第一行可以是 // @options: {"max_output_tokens": 2000, "timeout_ms": 60000}。max_output_tokens 默认 10000；超长保留头尾，全文写到临时文件。timeout_ms 默认不设。

codemode.mode：on（默认）保留已声明工具，并在描述里注明脚本怎么调；only 把这些内置和扩展工具从模型面前藏起来，改由 codemode 描述列出。codemode.inlineBudget 默认 3000（按字符 / 4 估算）。放不下的用 searchTools() 找。

边界

  • 虚拟机内存 256 MB，超出抛 InternalError: out of memory。
  • 脚本不能再启动另一个 codemode。
  • 没有定时器。等待一个永远不会完成、且没有工具调用挂着的 promise，会立刻失败。
  • models.classify() 和 generateImages() 每个脚本同时最多 4 个，多的排队。文档没有把这个 4 写成普通 tools.* 的并发上限。
  • 输出超过 16777216 个字符（文本加 base64 图像）或 text() / image() / console 调用超过 100000 次，脚本失败。

谁被自动打开

MCP 默认 exposure 是 codemode。这种服务器连上时 Pi 激活 codemode；deferred 服务器连上时激活 tool_search。没有 MCP 也要 codemode：在 settings 里写 "defaultTools": ["+codemode"]。不想自动打开：在 mcp.json 里与 mcpServers 并列写 "autoEnableCodemode": false。两条间接路径都没开、又存在非 direct 工具时，Pi 警告一次。

4对照

问题 direct deferred + tool_search codemode
模型第一次看见工具 请求里就有完整声明 先看见 tool_search，命中后下一次调用才有声明 默认不把 MCP 工具列进 codemode 描述；脚本里再搜索
调用形态 一次普通工具调用 加载之后也是普通工具调用 一次 codemode 调用，里面是 JS
回到模型的内容 该次工具结果。MCP 文本超过 20 KB 时中间换成截断标记，全文在临时文件 加载之后与 direct 相同 只有脚本输出。脚本拿到完整 MCP CallToolResult
大结果 截断发生在进模型之前 同 direct 脚本里先过滤。bash 在脚本中最多拿到约 1 MiB，再长则保留头尾各 512 KiB
失败是否回滚 该次调用已经发生 同 direct 失败前的工具调用不撤销
官方建议的场合 小、常用的工具集 大工具集，发现后要直接调用 要组合、并行或过滤；也可不接 MCP，用来跑分类器和出图
会话里留多久 一直在活动工具集里，直到被关掉 加载记录在转录里，留在该分支 脚本调用不依赖活动工具集，/tree、resume、fork 之后仍可调用 codemode / deferred 工具

同一张 exposure 表里还有 hidden：注册了，但是够不着。扩展还可以用 model-only（活动时声明给模型，别的工具不能再调用它）。tool_search 自己就是 model-only。这两档不负责把业务工具交到模型手里。
