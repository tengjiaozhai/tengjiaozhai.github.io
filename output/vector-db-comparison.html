四个向量库完整对比

Qdrant · Milvus · pgvector · Chroma — 数据点截至 2026 年初，用于 AgentScope RAG 及通用检索选型。量级与资源数值为典型参考，非产品承诺。

1身份定位 — 它们根本不是同一类东西

Qdrant
独立专用服务

为向量检索单独设计的生产级服务，Rust 全栈实现，单二进制/单容器即可部署。

语言 Rust · License Apache-2.0
厂商 Qdrant 公司（有云服务）
Milvus
分布式专用服务

云原生分布式架构（存算分离），面向十亿级与水平扩展设计，LFAI 孵化项目。

语言 Go + C++ · License Apache-2.0
厂商 Zilliz（有云服务）
pgvector
PostgreSQL 扩展

不是独立数据库，是把 vector 类型 + 相似度运算符 + 索引装进 PG 内核的扩展。

语言 C（随 PG） · License PostgreSQL
维护 社区 + Crunchy Data
Chroma
嵌入式客户端库

追求零配置开箱即用，pip install 后在进程内跑，定位类似“向量界的 SQLite”。

语言 Python（核心重写中）· License Apache-2.0
厂商 Chroma（有云服务）

3架构形态 — 从“一个库”到“一个集群”

Qdrant：独立单进程服务

查询只经过一个二进制，存储目录即数据，可整体备份/迁移
HTTP / gRPC 客户端（Python/JS/Rust/Go…）
Qdrant 服务 HNSW 图（内存映射）+ payload 过滤引擎 + WAL
本地磁盘向量文件(mmap) + RocksDB(payload) + 快照/备份
另有进程内嵌模式 :memory:（AgentScope 默认 QdrantStore 即此模式），零外部依赖。

pgvector：长在 PG 内核里的类型

不是新服务。CREATE EXTENSION 后，向量只是表里的一列
任何 SQL 客户端 / ORM
PostgreSQL 内核 heap 表: id, title, embedding vector(1024), tsvector · HNSW/IVF 索引 · 成本估算器
PG 数据目录WAL 崩溃恢复 · 备份/流复制/PITR 全复用 PG 生态
向量可和其他列一起 WHERE/JOIN/建触发器——唯一能把向量搜索放进业务事务的选项。

Chroma：嵌在你的 Python 进程里

import chromadb 即用；磁盘文件 = 持久化，换个路径即拷贝
你的应用进程（Python/JS）
Chroma 核心（库内）HNSW 索引常驻内存 · SQLite 存元数据与段信息
本地目录sqlite/segment 文件；另有 client-server 与托管云形态
单机单写者模型：段定期合并，多进程并发写不安全，索引全内存意味着数据量受内存约束。

Milvus：存算分离的分布式系统

写路径先进消息队列（类 WAL），刷成段存对象存储，查询节点独立扩缩
Proxy 网关路由、合并多节点结果、TSO 排序
Data / Index / Query 三类节点 数据节点落段 · 索引节点可挂 GPU · 查询节点内存+磁盘(如 DiskANN)
etcd元数据
消息队列单机内嵌；集群 Pulsar/Kafka
MinIO/S3段文件
强大但重：独立部署最少也要 etcd + 对象存储 + 消息队列“三件套”（你服务器上的 Dify 版 Milvus 正是如此）。

6选型决策树

① 向量需要和业务数据同库 JOIN、走同一套事务/备份吗？（订单、用户、文档台账…）
需要 → pgvector（不需要新服务，别家都做不到同库事务）
不需要，独立检索服务没问题 → 看 ②
② 目标是几天内出 demo / 本地工具 / 个人知识库？
是 → Chroma（最快）；若后续要平滑转生产，可直接用 Qdrant 的进程内嵌/小容器起步
要长期生产运行 → 看 ③
③ 数据规模与扩展预期？
千万级以内、单机够 → Qdrant：过滤+混合检索+量化全内置，运维只要 1 个容器，是独立 RAG 服务的当前主流答案
亿级以上、多副本、GPU 索引、K8s 运维有人管 → Milvus：分布式是设计原点，别家没有这个上限
已有大规模 PG 集群，不想引入任何新组件 → pgvector（接受混合检索要自建）
落到你的服务器（DellServer）上：Milvus standalone 已在跑（Dify 依赖，19530 端口，占 3.6G 内存），pgvector 可借现有 PG 思路但需新容器，Qdrant/Chroma 未装。AgentScope 的 RAG 层若只做演示，用默认 QdrantStore(:memory:) 进程内嵌即可，一个向量库都不用新装；要持久化知识库时，新开独立 Qdrant 容器（6333 端口空闲）比往生产 Milvus 里灌数据更安全——隔离、零迁移成本、卸得干净。唯一必须部署的是 Redis（AgentScope 状态存储硬依赖）。
