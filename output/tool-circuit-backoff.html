1为什么需要退避

工具故障通常是持续性的（上游宕机、网络分区）。固定间隔重试会在故障期间反复撞墙；指数退避让探测间隔随故障持续时长指数拉长。

3一个熔断周期内部：OPEN 段 + 半开窗口

半开不是某个代数的专属状态，而是每个周期里"冷却刚结束、探测还没出结果"的窗口。代数只决定 OPEN 段多长。

OPEN（冷却中）工具已卸载，模型看不到时长 = f(代数)：30s / 60s / 120s … 封顶 600s
半开窗口冷却已过，工具放回时长不固定：直到模型下一次调用该工具
探测出结果二选一成功 → clearOpen 清零回 CLOSED
失败 → 代数 +1，进下一代 OPEN

4存的是代数，冷却是现算的

Redis 里永远只有两个字段；"30→60→120"这个指数序列从不进存储，每次读取时由代数现场推导。

🗄 Redis 持久化（每工具 1 个 hash）

gen:{flight} = { n: 3, at: 1754700000123 }

n = 第几代故障（HINCRBY 原子递增）
at = 本次熔断时刻（每次 trip 刷新）
没有 cooldown 字段，没有倒计时字段，没有 HALF_OPEN 标记

🧮 Java 现场推导（纯函数）

n=3 ──► cooldown = min(ceil(30×2²), 600) = 120s
at+120s ──► now ≥ ? ──► 未过=OPEN / 已过=半开
配置改了 ──► 存量数据无需迁移，重算即一致

冷却时长是"代数 + 配置"的纯函数，任何时刻可重算 —— 这是状态机能省掉到期标记的根本原因。

CircuitBreakStore.java L184-191 · 退避公式private long computeCooldown(long generation) {
    double raw = properties.getInitialCooldownSeconds()
        * Math.pow(properties.getBackoffMultiplier(),
                   Math.max(0, generation - 1));   // 指数部分 = n-1
    long cooldown = (long) Math.ceil(raw);          // 小数向上取整，冷却只长不缩
    return Math.min(cooldown,
        properties.getMaxCooldownSeconds());          // 封顶 600s，防探测饿死
}
CircuitBreakStore.java L162-177 · 到期判定（简化）public boolean isCooldownExpired(String toolName) {
    Object atObj = redis…get(genKey(toolName), "at");
    if (atObj == null) return true;   // 不在 OPEN → 视为已过（fail-open）
    long openedAt = parseLong(atObj);  // 脏数据也放行，不锁死工具
    long cooldown = getCooldownSeconds(toolName); // 读 n → 现算
    return System.currentTimeMillis()
        >= openedAt + cooldown * 1000L;  // 绝对时间戳比较，无倒计时状态
}

6五个设计决策

决策做法理由 / 不这样会怎样
代数驱动，不是失败次数 连续 3 次失败被 threshold 归并成一次 trip，n 只 +1 惩罚的是故障持久度。不这样：一次网络抖动连败 3 次就触发长冷却，误伤瞬时故障
封顶 max = 600s min(…, 600)，指数序列到 n=6 后不再增长 恢复感知延迟有上限。不这样：故障持续一天后冷却几小时，上游恢复了模型也很久才发现
成功即清零 探测成功 → clearOpen 删整个 gen key → 下次从 30s 重新开始 既往不咎：半开成功是上游恢复的强信号。不这样：历史故障累积惩罚，恢复后仍被长冷却拖累
推导不存储 只存 n 和 at，cooldown 每次现算 改配置（multiplier/initial）无需迁移存量数据；无倒计时字段，重启/多实例天然一致。不这样：存剩余时间需要后台维护，且配置一改数据就作废
fail-open 判定 at 缺失或解析失败 → 一律视为"已过冷却" 坏数据最多让工具提前放回。不这样：一个脏 key 就能把工具永久锁死，熔断机制自己变成故障源
指数退避不是"存了一个越来越大的数"，而是"代数越熔断越高，冷却永远是代数的指数函数"。
