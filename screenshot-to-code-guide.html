3. 端到端执行流程

从"用户上传截图"到"代码出现在屏幕上"，一共经历 9 个关键节点：

4. 前端：从上传到发送请求

4-1. App.tsx — 大脑

App.tsx 是整个前端的"神经中枢"。它不做渲染，只做状态管理和流程编排。关键函数：

函数触发时机做了什么
doCreate()用户上传图片/视频后点击生成重置状态，调用 doGenerateCode 发起新建
doCreateFromText()用户只输入文字描述设置 inputMode="text"，调用 doGenerateCode
doUpdate()用户在侧边栏输入修改指令拼装历史记录，以 generationType="update" 重新请求
doGenerateCode()被上面三个函数调用创建 Commit 对象，调用 generateCode() 建立 WS 连接
cancelCodeGeneration()用户点击取消关闭 WebSocket，触发 onCancel 回调
reset()新建项目清空所有状态，回到初始界面

4-2. generateCode.ts — WebSocket 客户端

这个文件只做一件事：建立 WebSocket，发送参数，监听消息，把每种消息分发给对应的回调函数。

// 简化后的核心逻辑
const ws = new WebSocket(`${WS_BACKEND_URL}/generate-code`);

ws.addEventListener("open", () => {
  ws.send(JSON.stringify(params));   // 一次性把所有参数发给后端
});

ws.addEventListener("message", (event) => {
  const response = JSON.parse(event.data);

  if (response.type === "chunk")           callbacks.onChange(response.value);
  else if (response.type === "setCode")     callbacks.onSetCode(response.value);
  else if (response.type === "toolStart")  callbacks.onToolStart(response.data);
  else if (response.type === "toolResult") callbacks.onToolResult(response.data);
  // ... 其他 8 种消息类型
});
💡 WS 消息类型共有 12 种（chunk / status / setCode / error / variantComplete / variantError / variantCount / variantModels / thinking / assistant / toolStart / toolResult），覆盖了 AI 生成的所有阶段。

4-3. 状态管理（Zustand Store）

useProjectStore

存储所有"项目内容"：commits（版本历史）、referenceImages（参考图）、inputMode、variants（多个 AI 并行输出）。

useAppStore

存储"UI 状态"：appState（INITIAL / CODING / CODE_READY）、selectedElement（选中的 DOM 元素）、updateInstruction（修改指令文本）。

5. 后端：Pipeline 中间件链

routes/generate_code.py 使用经典的责任链模式——请求依次经过 6 个中间件，每个只做一件事：

每个中间件调用 await next_func() 把控制权传给下一个——如果中间出错，直接 throw_error() 关闭连接，不会继续执行。

5-1. 参数提取 (ParameterExtractionMiddleware)

接收 WebSocket 传来的 JSON，校验并解析出以下关键字段：

字段类型用途
generatedCodeConfigStack目标框架（html_tailwind / react_tailwind 等 6 种）
inputModeimage / video / text输入类型，影响 Prompt 组装和模型选择
generationTypecreate / update新建还是编辑，决定 Prompt 策略
promptUserTurnInput当前用户输入（文字 + 图片 + 视频）
historyList[PromptHistoryMessage]多轮对话历史，用于 update 场景
fileStateDict | None当前 HTML 文件快照，供 Agent 编辑

5-2. 模型选择 (CodeGenerationMiddleware 内)

根据你提供的 API Key 组合，自动选择模型列表，并行跑多个 variant（变体）：

# 有哪些 key，就用哪些模型的组合
if   gemini + anthropic + openai: models = ALL_KEYS_MODELS_DEFAULT
elif gemini + anthropic:          models = GEMINI_ANTHROPIC_MODELS
elif anthropic only:             models = ANTHROPIC_ONLY_MODELS
elif openai only:               models = OPENAI_ONLY_MODELS
# 视频模式强制使用 Gemini
if input_mode == "video":         models = VIDEO_VARIANT_MODELS
⚠️ 默认情况下会同时跑 4 个 variant（编辑模式为 2 个），消耗 4 倍的 Token，用完后由前端让用户选择最好的一个。

backend/prompts/ 负责把用户的截图、文字、历史记录"翻译"成 AI 可理解的消息列表。核心是三种策略：

决策函数 derive_prompt_construction_plan() 在 prompts/plan.py 中，根据 generation_type、history 是否为空、file_state 是否存在，选出一种策略。

7. Agent 引擎：多轮工具调用循环

backend/agent/engine.py 是整个项目最核心的部分——它实现了一个 "Think → Tool → Think → Tool → …" 的自主循环，直到 AI 完成代码生成为止。

7-1. 工具系统 (agent/tools.py)

目前 Agent 可以使用的主要工具：

工具名作用执行后

其他工具视配置可扩展结果以 toolResult 消息返回前端

7-2. Provider 适配层 (agent/providers/)

不同的 AI 厂商 API 格式各不相同，providers/ 目录通过统一的 ProviderSession 接口抹平差异：

Gemini

视频模式专用，支持直接传入视频 URL

9. WebSocket 消息类型速查

后端发给前端的所有消息都是这种格式：{"type": "...", "variantIndex": 0, "value": "..."}。下面是完整的消息类型列表：

type触发时机前端处理
status生成各阶段进度显示在侧边栏状态栏
chunkAI 输出流式文字片段追加到当前 variant 代码（历史遗留）
setCode工具写入文件时直接替换预览区的完整代码
thinkingAI 思考过程文字折叠展示在对话面板
assistantAI 回复的普通文字展示在对话面板
toolStart开始执行某个工具显示工具名和输入摘要
toolResult工具执行完毕显示工具输出结果
variantCount确认本次 variant 数量初始化预览面板数量
variantModels调试模式下发出在 UI 标注每个 variant 使用的模型
variantComplete某个 variant 全部完成标记该 variant 为完成状态
variantError某个 variant 出错标记为错误，显示错误信息
error致命错误显示 toast，关闭连接

10. 版本管理：Commit 系统

前端用类似 Git 的 Commit + Head 模型追踪所有生成历史，让用户可以随时回退：

每个 Commit 包含若干 variant（并行 AI 输出），用户可以切换查看，选定后继续编辑。selectedVariantIndex 标记当前选中的 variant。

💡 前端的 commits 是一个 Record<hash, Commit>，head 存储当前 Commit 的 hash，类似 Git 的工作原理。

12. 本地启动方法

启动后端

# 安装依赖
cd backend
pip install poetry
poetry install

# 配置 API Key（任选其一）
echo "OPENAI_API_KEY=sk-..." > .env
echo "ANTHROPIC_API_KEY=sk-..." >> .env

# 启动
poetry run uvicorn main:app --reload

启动前端

# 安装依赖
cd frontend
npm install

# 启动开发服务器
npm run dev

# 浏览器打开
http://localhost:5173
💡 也可以用 docker-compose up 一键启动，但不支持热重载开发。
