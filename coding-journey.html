v040
确定性编辑状态 + 完整序列化器
难点: contenteditable 修改后无法稳定定位元素；DOM clone 与 original 状态同步问题
技术原理: registry Map 存储 {original, clone, container}；data-tinno-edit-id 属性标记；collectState() 收集 innerHTML+style；version:2 状态格式兼容
v041
转义 </script> 防 HTML 解析破坏
难点: 序列化 JSON 中若含 </script> 字符串，浏览器提前关闭 script 标签，页面整体崩溃
技术原理: JSON 序列化后用正则将所有 </script> 替换为 <\/script>；反序列化时 JSON.parse 不受影响
v044
Toolbar 可见性 Bug 修复
难点: 编辑模式进入后 Save/Exit 按钮仍为 display:none；状态机转换没有同步 DOM 显示
技术原理: setToolbarButtonVisible() 在 syncToolbar() 中显式设置 display:inline-block；Playwright 集成测试验证按钮 is_visible()
v046
Hover 激活 + 自动保存（去除 Toolbar）
难点: 可见 Toolbar 与拖拽操作冲突；File System Access API 只允许用户手势触发写入
技术原理: mouseover/mouseout 替代按钮切换；首次编辑时 showOpenFilePicker 获取 writable handle 并缓存；onblur/focusout 触发 autosave；不支持时降级 download
v049
重构：移除 deck 模式，scroll 唯一路径

Inline Editor 设计规范2026-05-12

目标

浏览器内联编辑 + 拖拽 + File System Access API 直接覆写原 HTML，无需重跑脚本。

状态模型

  • 展示模式: 翻页/导航/动效正常
  • 编辑模式: hover 激活，元素变 contenteditable + 可拖拽
  • 单一变量 window.__editMode 控制进出

坐标体系

所有坐标用相对父 .slide 的百分比，不用 px。原因：--stage-w/h 由 CSS 变量决定，百分比在不同屏幕等比复现。

可编辑范围 (V1)

  • 文字: .tinno-main-title / .tinno-share-title / .tinno-issue / .tinno-content-box
  • 拖拽: 仅顶层绝对定位元素
  • V1 排除: .tinno-content-block（flex 容器坐标系复杂）
Markdown 图片版面安全设计2026-05-11
TINNO PORTRAIT Z-INDEX LAYERS / Tinno 竖版模板层级栈

问题根因

  • 标题 white-space:nowrap + 无安全边界，长标题溢出
  • 内容卡片 flex 权重强制撑满，短内容大面积空白
  • 10 张图片被 auto-fit 网格压成极窄列
  • 远程 Markdown 图片 URL 未缓存，离线失效

推荐方案: 确定性资产管线

  • 本地图片复制到 images/generated/
  • 远程图片优先下载缓存
  • 图片按版面容量分页，单页数量受控
  • 内容块使用自然高度，不强制撑满

从 94 次提交 + 13 份设计文档提炼的 10 条工程洞察
CSS 变量是响应式舞台的基石
min(100vw,56.25vh) 配合 CSS 变量一行解决 9:16 等比缩放，远比 JS 计算稳健。所有尺寸用 calc(var(--stage-w)*系数) 确保任意分辨率下比例一致。
JSON 注入 HTML 必须转义 </script>
序列化到 <script type="application/json"> 时，内容含 </script> 会提前关闭标签。这是"几乎不会被测试覆盖"的隐性 Bug，必须用正则主动防御。
networkidle 是截图的陷阱
Google Fonts 在无网环境永不空闲。两段等待（domcontentloaded + load/ignore）才是生产级截图的正确姿势，文档中反复提及。
Windows 文件 URL 有盘符大小写陷阱
file:///c: 与 file:///C: 是不同 URL。跨平台路径匹配前必须统一大写盘符。这类"只在特定 OS 上出现"的 Bug 最难发现。
文件名必须纯 ASCII
中文文件名经 URL encode 变 %xx 序列，跨平台传输必然乱码。NFKD normalize 后过滤非 ASCII 是根治方案，不是治标的 encode/decode 配对。
Python 拼接 JS 比直接写 JS 更可控
editor_js.py 用 Python 字符串拼接生成 JS，可在渲染时动态注入初始状态，也可在 Python 层 unittest 测试 JS 内容（无需启动浏览器）。渲染层与逻辑层分离带来可测试性。
拖拽坐标系用百分比不用 px
设计规范明确：拖拽坐标用相对父 .slide 的百分比。--stage-w/h 由 CSS 变量决定，百分比在不同屏幕等比复现，px 会失准。
用 SKILL.md 约束 AI 行为是 Prompt 工程
v093 通过写"图片完整性铁律"约束 AI 不丢图。规则的可执行性比描述性更重要——"失败必须中断重试"比"尽量保留图片"有效 10 倍。
删除比添加更有价值
v049 删除 deck 精简 100 行，v074 移除 story-card-title h2，v027 精简 skills。每次大胆删除都带来更清晰的架构和更低维护成本。过度设计的对面是敢于做减法。
设计文档是代码的上下文，不是注释
13 份 docs/ 文档记录每个架构决策的 Why（为什么放弃方案A选方案B），这些信息不出现在代码或 commit message 中。设计文档让未来的你（或 AI 代理）能理解决策背后的约束。
