# Agent 求职经验分享及面经（一）

## 这一篇覆盖什么

一位后端转 Agent 方向的求职者的**实战记录**：前半是方法（JD 拆解、面试复盘、反问设计），后半是 20+ 场真实技术面题库（小厂 AI 应用 / 企业软件 / 健康医疗 / 出行物流 / 汽车软件）。边界是「个人一手的求职过程」，不含任何招聘方视角，也不含 offer 结果与薪资。

- 覆盖：三条可复用做法（JD 模拟出题、复盘 Skill 化、反问设计）、大量真实面试题、部分 JD 原文。
- 不覆盖：成功率与最终结果、面试官评分标准、不同公司难度的可比性。

| **把重复性求职准备做成 Skill**（JD 拆解模拟出题、面试录音复盘），而非每次手工 | [[wiki/concepts/STAR法则]] |

## 与其他笔记的重叠点

- **与 [[wiki/concepts/STAR法则]] 的关系是本篇最重要的变化**：那页此前明确写着「本仓没有面试、求职、表达类记录，这条是纯外部引入，零实践样本」。**本篇是第一条实践样本**，且它补上了 STAR 原文没写的一环 —— 反问环节。
- **与 [[wiki/synthesis/学习方法的两条轴]] 的关系**：那页把「输入侧（领域速通）」与「输出侧（STAR）」配成一对，并指出缺第三条轴「迁移验证」。本篇提供了一个具体的迁移验证形态：**模拟题的命中率**，虽然只是自述数字。
- **与 [[wiki/concepts/Skill-vs-Tool]] 的关系**：本篇「JD 拆解做成 Skill」「复盘做成 Skill」两次实践，都落在判据一的「错了只是重跑一次」那一侧 —— 求职准备错了无非重新准备，不需要代码掌控。判据在这里是可用的：它预测了「该做成 Skill 而不是写死流程」。

## 本篇独有、别处没有的

1. **反问三问的具体设计意图**，尤其第二问「业务痛点」—— 不只是了解业务，而是「边听边思考你的解决方案，听完给出见解」，把反问变成二展示位。这一层 STAR 原文完全没有。
2. **两个流程的 Skill 化**：JD 拆解 + 模拟出题的输入是「JD + 我的复习进度」，复盘 Skill 的输入是「JD + 面试录音转文字」—— 都是**双输入**结构。
3. **真实的 Agent 岗位题库形态**：题目集中在「你做过的项目难点」「可用性怎么衡量」「spec 由什么组成」「为什么 Claude Code 写代码更强」这类，而不是算法题。这本身就是一份岗位能力画像。

## 待处理

- 「40–45% 命中率」是作者自述单点值，无样本量、无对照，只能 `unverified` 引用。
- 20+ 场面试的**结果全部缺失**（过没过、差在哪），因此无法从这份材料反推「哪种准备方式更有效」。
- 题库部分只做了整体登记，未逐题归类。若要用来做自测，需要先按能力维度切分。
