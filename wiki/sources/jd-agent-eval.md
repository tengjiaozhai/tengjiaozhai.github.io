# 京东 Agent 评测体系技术拆解

> 外部裁剪件。公众号「银翼AI评测室」2026-10-23 发布，**第三方拆解，不是京东官方发布** —— 所有数字都是拆解者从公开信息汇总的，本页 `status: unverified`。
> 它按大厂通用的六大模块（指标体系 / 评测集治理 / 分层归因 / 评估器 / AgentOps / 安全红队）逐项拆京东，把五块资产（言犀平台、OxyEcomBench、京小智、JoyCoder、安全可信平台）拼成一张图。
> 价值在于**参数级细节**（6300 实例、29 任务、P0–P3、200+ 攻击手法），代价是数字无法回溯到一手材料。

## 这一篇覆盖什么

- 覆盖：京东的四层业务结果金字塔、评估器「能算的不问模型」的性价比阶梯、自建基准 OxyEcomBench 的三个设计决策与「立尺派」的战略取舍、分层归因（多智能体角色边界 + NL2SQL 四步兜底）、评测集治理（真实数据 / 专家验证 / 诚实分级）、三条业务线的 AgentOps、安全红队的双线布局。
- 不覆盖：任何可复跑的实现；LLM 裁判方法论（文中自评「着墨少」）；轨迹级回放。
- 定位：**战略拆解**。它对「评测该往哪投」的判断（参评派 / 内嵌派 / 立尺派）比技术细节更有价值。

## 与其他笔记的重叠点

- **指标体系**：与美团的「三级桥」是同一问题的两种解法 —— 美团显式建桥梁指标，京东直接让评测和经营说同一套话（GMV / 转化率 / 渗透率）。取舍见 [[wiki/synthesis/大厂Agent评测体系对照]]。
- **分层归因**：与 [[wiki/concepts/失败归因与回归任务]] 的「首个错误定位」互补 —— 那边定位**轨迹里的第 k 步**，这边把归因做进**系统结构**（哪个智能体负责），失败不用复盘报告就能落到责任人。
- **难度分级**：与 [[wiki/concepts/任务质量自检]] 的「诚实分级」一致，京东多给了一条判据：**共识不稳定的任务不硬标难度**。

## 本篇独有、别处没有的

1. **三种评测战略**（参评派 / 内嵌派 / 立尺派）—— 把一个「要不要自建基准」的技术问题提升成战略问题。
2. **自建基准的双螺旋**：同一笔评测投入既是行业尺子又是自家训练靶场（OxygenVLM 依托 OxyEcomBench 迭代），「造题、提分、收钱」三段咬合。
3. **立尺派的公信力三道对冲**：方法全透明、第三方同测（20 个外部模型同榜）、不回避对自家叙事不利的结论（「通用模型在电商域优势收窄」）。
4. **视觉证据优先**：评测集优先选「关键证据在图像里而非文本里」的案例 —— 防作弊的通用手法（文本先验蒙不过去）。
5. **诚实的分级**：P0–P3 只应用于能达成稳定专家共识的任务，共识不稳的不硬标。
6. **归因即分层兜底**：NL2SQL 的四级降级链，每级的失败原因与修复动作一一对应（词表没配 / 语义没学上 / 别名没建 / 偏好没积累）。
7. **稳定性本身是被测对象**：同一批样本多次调用看输出抖动；单行补全要求 1 秒内返回。
8. **安全侧的三路互证**：黑灰词 + NLP 语义 + 生成式辨识，恶意识别算法四种以上，识别准确率 ≥95%。
9. **七条可借鉴清单**（评估器阶梯 / 行为数据 / 基准三决策 / 双螺旋 / 公信力 / 按角色归因 / 翻译成经营语言）—— 本页最可复用的部分。
