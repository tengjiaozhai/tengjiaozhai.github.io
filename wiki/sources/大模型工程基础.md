## 与其他笔记的重叠点

- **动态变量注入**：`thoughts/076` 讲提示词里怎么注入变量，与主章的「动态内容必须放最后」直接冲突 → [[wiki/concepts/KV缓存与提示词缓存]] 的「取舍与边界」
- **系统提示词优化**：`thoughts/081` 从百炼（DashScope）的隐式缓存角度讲了同一件事，含 20% 计费的实际数字
- **上下文压缩**：压缩重写历史等于破坏前缀，每次压缩后第一次请求必然全量重算 → [[wiki/concepts/上下文压缩]]
- **工具缓存**：容易与主章的「提示词缓存」混淆，两者失效机制相反 → [[wiki/concepts/工具缓存]]
- **关闭深度思考**：`thoughts/041`（登记于 [[wiki/sources/thoughts-路由与智能体协作]]）从反方向讲同一件事 —— 外层 ReAct 循环已经调度了推理，内层再开 thinking 是重复付费。这是附章「默认什么都不加」的本仓版本
- **任务层规划**：附章的 ToT 是单次推理内的搜索，与 [[wiki/concepts/Plan-Execute]] 的任务级拆解不同层，可嵌套
- **评测口径**：附章 §8 的消融与三组指标，与 [[wiki/concepts/Agent评测]] 的 model swap / 消融分工是同一套判据

## 本篇独有、别处没有的

1. **KV Cache 的原理级解释** —— 从「生成第 N 个 token 要看到前面所有 token」推到哪里可以缓存，是本仓唯一讲清机制的
2. **「前缀必须逐字节一致」这条铁律的推论链** —— 不是「写得短」，而是「把稳定的放前面，把会变的挪到后面」
3. **Claude Code 的量化数字** —— 92% / 81%，本仓唯一的一组生产环境实测
4. **Anthropic 的原话**：「如果你正在构建 agent，却没有围绕 prompt caching 来做架构设计，那你其实正在把绝大部分利润空间白白留在桌上」
5. **四档推理策略的「Prompt 模拟 vs 工程实现」对照表** —— 本仓唯一一处把「看起来像」和「真的是」分开列的地方
6. **推理策略的选型与消融流程**（附章 §8）—— 五步：baseline → 实验组 → 三组指标 → 消融 → 成本收益
