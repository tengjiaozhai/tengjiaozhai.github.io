## 与其他笔记的重叠点

- **动态变量注入**：`thoughts/076` 讲提示词里怎么注入变量，与本篇的「动态内容必须放最后」直接冲突 → [[wiki/concepts/KV缓存与提示词缓存]] 的「取舍与边界」

- **上下文压缩**：压缩重写历史等于破坏前缀，每次压缩后第一次请求必然全量重算 → [[wiki/concepts/上下文压缩]]
- **工具缓存**：容易与本篇的「提示词缓存」混淆，两者失效机制相反 → [[wiki/concepts/工具缓存]]

## 本篇独有、别处没有的

1. **KV Cache 的原理级解释** —— 从「生成第 N 个 token 要看到前面所有 token」推到哪里可以缓存，是本仓唯一讲清机制的
2. **「前缀必须逐字节一致」这条铁律的推论链** —— 不是「写得短」，而是「把稳定的放前面，把会变的挪到后面」
3. **Claude Code 的量化数字** —— 92% / 81%，本仓唯一的一组生产环境实测
4. **Anthropic 的原话**：「如果你正在构建 agent，却没有围绕 prompt caching 来做架构设计，那你其实正在把绝大部分利润空间白白留在桌上」
