# RSI 学习

## 这一篇覆盖什么

一篇**把 RSI（递归自我改进）当工程问题拆解**的自有笔记，围绕四个问题展开：怎么评估好坏、怎么判断改进是好的、标准怎么适配场景、接受或回滚由谁决定。边界是「概念框架与决策架构」，不含任何实验数据、不含具体实现代码。

- 覆盖：RSI 五阶段闭环、五个核心组件（尤以 Evaluator 为关键）、两层递归的区分、四个问题的决策取舍、可靠性三层次。
- 不覆盖：任何一次真实的自我改进实验、成本数字、Darwin Gödel Machine 之外的实现细节（只提到它的沙箱与人工监督）。

## 与其他笔记的重叠点

- **与 [[wiki/concepts/Agent评测]] 的重叠**：那页讲「怎么设计一次评估」，本页讲「怎么用评估来驱动自我改进」。共享三类裁判、共享「评估对象是模型+Harness」，但本页多了一层 —— **评估结果要反过来决定版本是否升级**。
- **与 [[wiki/concepts/评测标准对齐]] 的接口**：Reward Hacking 在两页都出现，但角度不同。那页讲「判定标准怎么算稳」，本页讲「标准被优化对象篡改」这一具体失效模式。
- **与 [[wiki/concepts/失败归因与回归任务]] 的衔接**：本页的「诊断 → 提案」正是那页归因链路的下一步。那页止于「定位到哪一类失败」，本页接着问「定位之后改什么、怎么证明改对了」。
- **与 raw 里的 [[wiki/sources/迈向自我改进的综述论文]] 的关系**：那篇是学术综述（定义边界、四个进化目标、七个前沿维度），本篇是**工程决策视角的中文整理**。两者对「Proposal → Feedback → Optimization」循环的描述一致，但本篇补了综述没细讲的「谁来决定接受」这一治理问题。

## 本篇独有、别处没有的

1. **四个问题的完整决策表**，尤其「AI 直接决定 / 人工逐次 / 规则自动+人工监督」三选一的取舍。
2. **「可靠性三层次」的分解** —— 明确说「真实能力全面提升通常无法保证」，这是对 RSI 叙事的降温。
3. **好的改进提案必须含「可验证的假设」这一项**，且给了一个可以照抄的四格模板。
4. **评估标准本身也要优化**（测试题会失去区分度），但优化者不能是候选 Agent。
5. **「如果 AI 能力超过评估器的判断范围，评估器怎么知道它进步了」** —— 作者自认这是最值得深究的方向，也是本页的收口。
