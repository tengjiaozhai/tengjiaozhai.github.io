# 掌握 STAR 面试法

> 外部裁剪件。《哈佛商业评论》中文版文章，作者 Marlo Lyons（职业教练），经 36氪 授权转载，机翻痕迹明显。
> 原文 <https://www.36kr.com/p/3206765036782724>。**方法论文章，无数据、无实验**，故 `status: unverified`；STAR 本身是行业通行框架，本页记的是这篇怎么讲它。
> 本仓学习域的第二篇，见 [[wiki/concepts/STAR法则]]。

## 这一篇覆盖什么

- 覆盖：STAR 五段结构（Situation / Task / Action / Result + Takeaways）、每段的句数配额、10 + 5 个常见问题、五步准备法、三段完整范例。
- 不覆盖：STAR 的出处与有效性证据；不同行业/文化下的适用性差异；技术岗深挖层的补充策略。
- 形态：**教学文章 + 模板库**。三段范例是教学样例（销售丢单、SaaS 性能优化、跨国团队冲突），不是真实候选人。

## 本篇独有、别处没有的

1. **段长配额**（1–2 / 1 / 3–5 / 1–2 句）—— 最可操作的一条，也是多数人失败的地方：把「行动」讲成了「情境」的延长。
2. **Takeaways 这一段是本文明确加的补丁**：失败故事缺了它，就只是失败；有它，才变成自我认知的证据。
3. **「目标不是死记硬背，是建立能调整的基础」** —— 明确了练习的验收标准不是背熟，是应变。
4. **一例多用**：同一个冲突故事可以答「跨团队协作」「推进目标」「担心项目失败」三种问法 —— 准备的是可重组素材，不是答案。
5. **线上要点清单**：把想突出的能力列成 8 条（团队合作者 / 问题解决者 / 沟通 / 技术专长 / 分析思维 / 战略思考 / 结果导向 / 情商），回答时逐条打勾。
6. **三段完整范例**，可以直接当结构模板读（尤其「结果 → 收获 → 与该岗位的关系」这个结尾写法）。
