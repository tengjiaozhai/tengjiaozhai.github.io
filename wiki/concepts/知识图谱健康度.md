# 知识图谱健康度

## 一句话定义

用图结构而不是内容质量判断知识库是否在退化：哪些页孤立、哪些页群内部松散、哪些页在维系多个领域——三个指标都能机器算，不依赖人读全文。

## 我目前的判断

**「断链 + 孤儿」是健康度检查的下限，不是全部。** 本仓 `tools/wiki-lint.mjs` 现在查六项：断链、孤儿、frontmatter 结构、`raw_digest` 漂移、重复概念、过期。原文补了两类本仓没有的信号：

1. **低内聚社区**（cohesion < 0.15）：一群页互相引用稀疏 → 这个领域其实没织起来，只是被归在了同一标题下。
2. **桥接节点**（连接 3+ 集群）：维系多个领域的关键枢纽，删它代价最大。

判断：**本仓现在不需要社区检测**（80 页，划分不稳），但「桥接页 / 稀疏区」这两个说法值得先进 schema 的语汇。重估锚点取原文给的规模线：约 100 个 source 时 `index.md` 仍够用（[[wiki/sources/llm-wiki-pattern|gist]] §Indexing and logging），本仓 44 个 source 远在安全区内。依据 [[wiki/sources/llm-wiki-app-readme|README 裁剪件]] §5–6。

## 关键机制

| 指标 | 判据 | 含义 |
|---|---|---|
| 孤立页 | 度 ≤ 1 | 只被 index 或无人引用 |
| 稀疏社区 | cohesion < 0.15 且 ≥ 3 页 | 实际边数 / 可能边数，Louvain 划分后计算 |
| 桥接节点 | 连接 3+ 集群 | 跨领域枢纽 |

配套动作：知识空白可一键触发「深度研究」（LLM 读 `overview.md` + `purpose.md` 生成检索主题）。本仓的等价物是 `index.md` 里的「待建页面」——**人工版知识空白清单**，效果等价，代价是每次得有人写。

## 我的实例

本仓当前实跑：`node tools/wiki-lint.mjs` → 76 页，0 项，六类全零（2026-10-22）。

这个 0 **不能反推结构健康**：一个所有页都只连 `index` 的库同样报 0 项。本仓真正在起作用的是两处手工维护——`index.md` 的「待建页面」缺口清单与各页的 `## 冲突` 段。

## 取舍与边界

- **不引入 Louvain**：社区检测需要图足够稠密。本仓 42 个 source 页多数只连 1–2 个 concept，划分结果会随一次 ingest 大幅抖动，噪音大于信号。此条为**推断**，未做实验验证。
- **失效条件**：source 数越过约 100 的量级（原文锚点），或某次 lint 报 0 项但你实际搜不到东西。
- **不拿度数当唯一指标**：本仓 `index.md` 是天然 hub，所有页都连它，度数会被污染——与 [[wiki/concepts/关联度模型|关联度模型]] 里 Adamic-Adar 修的是同一个病。

## 待澄清

- cohesion 阈值 0.15 的来源与适用范围（README 未给依据）。
- 「孤立页度 ≤ 1」在强制每页至少一条出站链接的库里（本仓 §5.1）是否还成立——本仓的孤儿定义是「无入链」，比它更严。
