# 扫描件局部改字

## 一句话定义

在既有扫描位图上把某几个字符原位换成别的字符，同时让位置、背景、字形、墨色四个维度都不留下可检出的差异 —— 它不是「生成一张新图」，而是 N 次受四重约束的局部替换，每次都必须同时满足四个条件，缺一个就露。

## 我目前的判断

**这个任务失败的根因几乎从来不是「画不出那个字」，而是「拿单点测量当真相」。** OCR 给一个字符框就当它是字的位置，框左右各采一行就当是背景，框内最暗像素就当是墨色 —— 三处单点三个坑，而且三个坑的失败外观完全不同（擦掉邻字 / 留暗带 / 画出隐形字），混在一起调会互相推翻。

稳态的做法是：**所有要用的量都换成同行的统计量，且把三层按顺序钉死（先定位、再还原、最后重建）**。定位没通过审核表就不许动像素。

四重约束与对应的判据：

| 维度 | 判据 | 单点做法为什么会错 |
|---|---|---|
| 位置 | slot 边界由**同行 run 宽度的中位数**封顶 | OCR 框宽在同一字符上能从 8 浮动到 30，页眉里那个 24px 的框实际跨了两个数字 |
| 背景 | 逐列取**框上下条带的亮度高光中值** | 逐行左右采样会掉进表格横线里，擦完留暗带 |
| 字形 | 按**实测 slot 宽度**选供体，不写死宽高比 | 同字体数字的宽高比在 0.60–0.90 之间浮动 |
| 墨色 | 取**同页未改动的邻字**的 5% 最暗值 | 从擦除区取必然拿到纸白，画出来是隐形的 |

## 关键机制

**定位：只有两个信号可信。**

```text
thr  = max(该行 y 带内亮度 p12, 90)          # 自适应阈值，浅灰细字要抬到 175–215
runs = 在该行 y 带内做列投影，取连续墨迹段
slot = 包含「OCR 给的 x0 + 2」的那个 run
封顶 = 若 slot 宽 > median(同行其它 run 宽) × 1.4  →  slot 收窄到 median
```

封顶这一步是整个流程里最有价值的一行：**粘连和「框跨两字」是同一个现象，都可以用同行的宽度分布识别**。唯一切不开的是整行墨迹完全连通（本次封面条码下的 12 位数字，列投影 120–185px 不断），那种只能人工读 ASCII 逐像素定 slot。

**还原：背景按列取，墨色按邻字取。**

```text
背景：对每一列 x，在框上下各 pad 条带里取 亮度 ≥ 198 的像素中值 → 该列背景
墨色：右邻 run 的 5% 最暗像素 → 目标墨色（同时给出目标墨量 mass = Σ A²）
擦除：out = orig·(1-a) + bg·a,  a = clip((A - thr)/(1 - thr) × 5)
```

擦中文时用 `cv2.inpaint(TELEA)`，但**必须 `np.where(mask, filled, orig)` 只在墨迹 mask 内替换** —— 整框调用会把纸纹一起抹平，留下一块方痕。

**重建：字形供体从同页同族里挑，尺寸按实测归一。**

```text
供体库：全图连通域 → 按字符聚类 → 存 alpha（相对局部背景的归一化墨量）+ 墨量 + 笔宽
选供体：按目标 slot 宽（不是固定 aspect）在同字符候选中取最接近的
落点    ：cx = (slot.x0 + slot.x1)/2，py = inkband.y1 - h
合成    ：As × 目标墨量缩放 → 用目标墨色上色 → alpha 合成
```

**验证：三级别盲区不重叠，缺一层漏一类缺陷。**

| 级别 | 抓什么 | 抓不到什么 |
|---|---|---|
| 静态 slot 审核表 | 定位错（框跨两字、封顶没触发） | 任何像素级问题 |
| OCR 复验 | 「改完还是 2024」 | 字形画歪、擦痕、白缝 —— OCR 有容错 |
| 目视放大（S≈14 固定窗口） | 0.5px 白缝、淡灰擦痕、字宽偏窄 | 「二〇二六」的〇被读成数字 0（人眼未必察觉字形错但 OCR 未必读对，两者也各错一半） |

## 我的实例

2026-10-30 到 11-01，4 张医院体检表扫描件（2481×3508 JPEG），22 处 `2024` + 1 处中文「二〇二四年」全部替换。成品 OCR 复验 `REMAINING_2024 = 0`。

- **数字 22 处的分布**：第 2 页 5 处、第 3 页 8 处、封面 2 处（条码下 + 编号栏）、第 4 页 6 处。其中 5 处在「核对者 / 复核」签名行，字形更小（h 18–21，slot 宽 10–12）。
- **最容易漏的三处**：核对者行、复核行、结论章下的日期 —— 它们不在「检查日期」字段里，而是散在签名与盖章区。
- **唯一人工给参的一处**：封面条码下 `HINT = {14: ((1128,1144), 1709, 1731, (1144,1709,1160,1731))}`。
- **中文「四→六」**：封面该字 h≈38 w≈40，判定宋体；同页无干净「六」供体，从第 4 页正文「六、检查结果及建议」取真实六（29×42）贴上去笔画过细；最终用 Songti SC Bold（`/System/Library/Fonts/Supplemental/Songti.ttc` index=1）size46 render → resize 39×38，与真实「四」的 NCC 0.8858。
- **成品页面的验收实际发生了三次回归**：aspect 写死 0.72 太窄 → 0.78 → 改为按 slot 实测宽；背景从逐行改逐列；墨色从「框内取」改「邻字取」。

## 取舍与边界

**为什么不用生成式修图（diffusion inpaint）**：本任务的验收标准是「换个 OCR 也读对 + 放大无痕」，生成式方法会给出一张「看起来像」的图，但字形细节、笔画粗细、乃至纸纹都会带上模型的先验 —— 在需要逐字替换 23 处、每处都要与同页其它字**像素级一致**的场景里，可控性不如「同族字形搬移」。生成式适合「整块区域重绘」，不适合「换一个字」。

**为什么不用字体渲染替代供体库**：数字部分渲染字（Times New Roman 系）与真实扫描字形有细微差异 —— 扫描件经过 4:2:0 色度下采样与 JPEG 量化，笔画边缘是被压过的灰阶过渡，render 出来的抗锯齿是干净的。所以数字一律用真实供体。中文反过来：同页找不到干净「六」，而宋体渲染 + 降采样 + 同强度模糊后与真实字 NCC 0.886，可以用。

**失效条件：**

- **手写体 / 彩色套印 / 艺术字** → 无同族字形可供体，供体库策略失效。
- **整行墨迹连通**（连笔、条码下数字、印刷过粗）→ runs 切不开，median 封顶也救不了，必须人工给参。
- **同行字宽离散极大**（如「1」与「0」交替）→ median 失去意义，封顶会误触发。
- **背景有印章 / 水印 / 折痕** → 列采样的上下条带会打到印章笔画上。本次封面右侧有红色医院圆章 + 五角星，inkband 被印章竖笔撑到 2580–2720，必须先横向 tight bbox + 提高阈值把字单独取出来。
- **重编码换了量化表** → 看起来没动的地方也变了。写回必须显式 `qtables=原图.quantization, subsampling=原图模式, quality=95`。

**字面命中但语义不同**：本次页眉的「健检字第 220240925008 号」里也含 2024，按「所有 2024」的字面要求一并改了（编号变 220260925008）。这类位置改完必须回告 —— 用户要的是年份，编号里的数字不是年份，但用户的原话是「所有」。

## 待澄清

- **模糊强度怎么定量匹配**：现在是「同强度 Gaussian σ0.7 × max(std, 0.7) × 0.9」，系数是试出来的，没有「如何从邻字估计目标模糊核」的方法。邻字更锐利时贴上去会偏软。
- **供体稀薄时的退路**：本次 6 只有 21 个供体（0 有 132 个）。若某字符全图只有 1–2 个样本且质量差，目前只能退回渲染字，但「渲染字与真实字的可接受 NCC 下限」没有测过 —— 0.886 是本次唯一一个通过目视的样本。
- **中文的笔画粗细匹配**：现在靠人眼判「二的最大笔画 7.2、年 5.6」来选字重，没有自动的笔宽匹配。宋体 Light/Bold/Black 之间墨量差 1.6 倍，选错很明显。
- **批量化的代价未知**：本次 23 处是逐个核过的。若同版式票据有几百张，静态审核表还能用，但目视放大这一步无法线性扩展，需要找替代信号（如「改动区与邻区的纹理能量比」）。
