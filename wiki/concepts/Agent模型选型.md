# Agent模型选型

## 一句话定义

选型不是选最强模型，而是在**能力上限 / 默认行为 / 延迟与成本**三条轴上，用自己任务集上的实测数据换一个可撤回的决策。公开榜单最多回答第一条轴。

## 我目前的判断

**三个层次，缺一层就会选错。**

| 层次 | 问什么 | 靠什么答 |
|---|---|---|
| 能力上限 | 给足机会能不能做到 | Pass@k / Best@k（见 [[wiki/concepts/Agent评测]]） |
| 默认行为 | 不做任何约束时它先做什么 | 中性提示下的行动阈值实验 |
| 值不值得 | 做到要花多少延迟与钱 | TTFT、p95、每任务成本、预算-能力曲线 |

**短预算领先不能外推。** 教材给的 RE-Bench 人机对照很说明问题：每个环境 2 小时总预算下，最佳 Agent 得分约是人类专家的 4 倍；8 小时人类略超；跨多次尝试合计 32 小时，人类约是 2 倍。选型如果只在短预算上比，测到的是**短任务排名**，不是长程能力。这和 [[wiki/concepts/Agent评测]] 里「接近饱和时能力的大提升只表现为分数小涨」是同一个陷阱的两面。

**延迟必须拆开看。** TTFT = 排队时间 + prefill（读入完整上下文），上下文越长 TTFT 越大；decode（tokens/s）决定后续出字速度，也直接决定思考时长 —— 50 tokens/s 生成 2000 个思考 token，光思考就 40 秒。这三个数混在一起报出的「耗时」没有解释力：教材的行动阈值实验里，两个模型的工具步数差 2.3 次（6.89 vs 4.56），但「到首次修改」的时间几乎相同（15.01s vs 14.48s）。工具步数、并行调用、模型延迟必须分开记。

**默认行为是模型属性，不只是提示词属性。** 同一 Harness、同一中性提示、同一任务仓库下，一个模型先广泛读仓再动手（4.67 个文件），另一个凭局部证据快速定位（3.56 个文件）；差距在局部任务最明显，在明确跨模块的任务上几乎收敛（7.00 vs 6.67 个文件）。判据也给了：换模型行为变、同模型跨 Harness 不变 → 更像模型效应；反之更像 Harness 效应。这条判据和「评估对象是模型 + Harness 组合体」是同一件事的正反面。

**便宜模型 + 重试可能更贵。** 成功率低触发重试，实际花费可能高于贵模型。该算的是每任务平均成本与成本-性能比，不是单价。

## 关键机制

**推理两阶段决定所有延迟指标**：

| 指标 | 由什么决定 | 用户感知 |
|---|---|---|
| TTFT | 排队 + prefill（随上下文长度增长） | 按下回车到第一个字 |
| 输出吞吐 / decode 速度 | tokens/s | 出字快慢、思考时长 |
| 思考延迟 | 思考 token 数 ÷ 速度 | 「想多久」；不同模型思考长度可差数倍，且与效果不一定正相关 |
| p95 尾部延迟 | 长尾请求 | 均值会被大量快请求拉低，掩盖少数人的严重卡顿 |

**成本有三个层次**：模型推理（输入 + 输出，含思考 token）、工具调用（外部 API + 沙盒 + 返回内容进上下文后的 token）、基础设施（向量库 / 队列 / 日志与追踪存储）。

两个放大因素最容易被漏记：**上下文累积** —— 每轮把全部历史重发，1k + 2k + 3k = 6k 而不是 3k，轮次越多差距越大；**工具返回的复利** —— 一次搜索返回 2–5k token，且此后每轮都作为输入反复计费。

**预算-能力曲线**：固定预算下的单点成绩不足以判断长程能力，应报告成功率随墙钟时间 / token / 工具调用次数变化的曲线，并在接近真实任务时长的多个预算点上比。

**异构组合**（轻量模型处理简单请求、强模型处理复杂推理）的收益必须先被评估证明超过系统复杂度，且要检查降级场景：把「9.9 和 9.11 哪个大」「家离洗车店 50 米该走路还是开车」当简单问题丢给轻模型，会直接错。

## 我的实例

**本仓没有选型实测。** 已记录的成本侧证据只有两处，都指向「同一件事的两个因子」而非选型数据：[[wiki/concepts/KV缓存与提示词缓存]] 里 Claude Code 的 92% 缓存命中 / 81% 成本下降、DashScope 约 20% 计费；[[wiki/concepts/上下文压缩]] 里「压缩不是免费的，摘要本身要花一次 LLM 调用」。

**本仓能立刻复用的一条**：把思考 token 单独记账。本仓所有对话都在产生思考 token，而 `wiki/log.md` 与各 source 页从没有一条记过它的占比 —— 这等于把成本里最不可控的一项当成了零。

**一条方法论收益**：`Agent 评测方法论.md` 里 pass^k 的口径判断（回归集用 pass^k 防止洗分）在选型里同样成立 —— 客服、支付、权限变更场景优先 pass^k，写稿、出方案优先 pass@k，见 [[wiki/concepts/Agent评测]]。

## 取舍与边界

**单模型 vs 异构组合**：多模型协同要付两份账 —— 路由判错的代价 + 系统复杂度。教材要求「通过评估验证整体效益是否超过所增加的复杂度」，本仓判断是：在没有稳定回归集之前，异构组合只会让「这次变差是哪个模型的问题」变得不可答。

**榜单与自有任务集的关系**：公开基准提升两个百分点，与业务成功率无必然关系；新模型在自己的任务上出现回退（regression）是常态，必须实测。

**失效条件**：
- 评测集只覆盖短任务 → 预算-能力曲线必错，长程能力无法判断
- 只比单价不比重试 → 便宜模型的真实成本被低估
- 模型迭代快：本页引用的模型名（GPT-5.6-sol / Claude Sonnet 5 / Gemini）半年就会过期，可迁移的是判据不是排名

## 待澄清

- 预算-能力曲线的采样点怎么选（2h / 8h / 32h 是对着人机对照设计的，业务里对应什么刻度未定）。
- 行动阈值的测量协议能否移植到本仓：固定系统提示 + 工具 schema + 仓库 + 命令 + 轮次，每题三次，共 18 条轨迹 —— 规模不大，但本仓没有可比任务。
- 思考 token 的记账字段，本仓的日志格式里没有位置。
