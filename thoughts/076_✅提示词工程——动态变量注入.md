# ✅提示词工程——动态变量注入

> 来源: https://thoughts.aliyun.com/workspaces/6963289eb0fc2e001bb052eb/docs/6a6885b374e4030001f1a7ce

差旅是强时间敏感的业务。用户张口就是「明天出发」「下周去杭州」「订个后天的」——这些相对时间必须换算成绝对日期，而换算的锚点「今天几号、现在几点、今天星期几」只有运行时才有。所以「把当前时间喂给模型」是刚需。


最朴素的做法是在系统提示词里写一行 当前时间：{时间} 然后每轮填进去。功能上没问题，但是有坑。


提示词模板是死的（写在 .md 文件里），但有些值只有运行时才知道：今天几号、现在几点、这一轮用户问题被改写成了什么、当前用户的 API Key 是多少。把这些运行时才产生的值，在真正调用 LLM 之前塞进「发给模型的消息序列」里，就叫动态变量注入。


注入的「目标」有三种，因为它们对 LLM 的可见性完全不同：
* 注入进**系统提示词文本** （模板占位符替换）——LLM 看得见，且是提示词的一部分；
* 注入成**一条独立消息** （新增一条 system/user 消息）——LLM 看得见，但独立于主提示词；
* 注入进**工具调用的入参** （改写 shell 命令、env 变量）——LLM **看不见** ，只在工具执行侧生效。




**什么叫前缀缓存（KV Cache）？** 这是理解 gogo-agent 为什么把注入拆成两层的关键。像百炼（Bailian）这类推理服务提供「隐式前缀缓存」：如果两次请求的消息**前缀完全一致** （逐字节相同），命中的那段前缀只按约 20% 计费。系统提示词通常是最长、每轮都重复的一段（本项目约 4000 token），最值得被缓存。


gogo-agent 的解法是**把「变得慢的」和「变得快的」拆开** ：日期、星期几一天只变一次，可以留在系统提示词里（一天内前缀仍稳定）；而秒级跳动的「当前时间」被踢出系统提示词，改成紧跟其后的**第二条独立 system 消息** 每轮注入。
